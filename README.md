# Trash zoo

その日出した食べ物のゴミを1つ放す。放した人だけが、他の人のゴミを見られる。
72時間で工場に運ばれ、二度と見られない。

いいね・コメント・フォロー・ユーザー名・プロフィール・ランキング・共有は実装しない。
評価手段を置いた瞬間に、発信側が最適化を始める。

- 公開URL: https://hino-333.github.io/trash-zoo/

## ファイル

- `index.html` — 画面の器
- `style.css`  — 色、影、跳ね方、呼吸
- `app.js`     — 島の生成、放飼場、個体、入場券、投稿フロー
- `scene.js`   — 放飼場の中の風景（空、遠景、擁壁、地面、ガラス柵、来園者）
- `data.js`    — 地域定義と初期個体（島が無人に見えないための最小限）
- `api/judge.js` — Claude の vision で判定し、飼育員の記録を返すサーバー側の関数
- `judge-prompt.md` — 飼育員のプロンプト（`api/judge.js` の中身と同じもの）

## 放飼場の中

動物園の展示場をそのまま作っている。

- 空と雲、地域ごとに違う遠景（街並み / ヤシ / 針葉樹 / ドーム / 寺 / アカシア / ユーカリ / 丘）
- 展示場の奥に不揃いな岩を積んだ擁壁、掘られた地面、まばらな草
- 手前にガラスと支柱の柵、映り込み、「入らないで」の標識
- 見に来ている人。じっと見る / 身を乗り出す / 写真を撮る / 指をさす / 子供が跳ねる / しゃがむ。
  地域ごとに人数も背格好も色も違う。顔はない。誰かは分からない
- ゴミたちは地面の上に奥行きをつけて置かれ、`weight_class` ごとに違う跳ね方をする

## 判定（Claude API）

`api/judge.js` は Vercel の Node 関数。切り抜き後の画像を受け取り、`claude-opus-5` の vision に渡して
`is_food_waste / name / category / weight_class / keeper_note / confidence` を返す。
スキーマは zod で固定しているので、形の違う返事は返らない。

**動かすには**

1. このリポジトリを Vercel に import する
2. Environment Variables に `ANTHROPIC_API_KEY` を入れる（キーはサーバーにだけ置く。クライアントには絶対に置かない）
3. Vercel 側の URL で開く。`/api/judge` が同じドメインにあるので、そのまま繋がる

GitHub Pages は静的配信なので `/api/judge` が無い。届かなかった場合は暫定の飼育員が答え、
投稿フロー自体は止まらないようにしてある（コンソールに警告が出る）。
別ドメインの API を使うときは、ブラウザで
`localStorage.setItem('trashzoo.judge','https://…/api/judge')` を一度実行すればそちらを見に行く。

## まだ繋がっていないもの

- **切り抜き** — いまはブラウザ内の自前処理（縁の色を基準にした領域拡張）。
  背景と対象の色が近いと残る。`@imgly/background-removal` などに差し替える前提。
  ここが甘いと部屋が写り、盛る余地が生まれる。このプロダクトの生命線。
- **保存** — いまは端末の localStorage。他人のゴミは初期個体で代用している。
  サーバーに移す際も、保存するのは切り抜き後の画像のみ。元画像は持たない。
