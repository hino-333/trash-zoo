# Trash zoo

その日出した食べ物のゴミを1つ放す。放した人だけが、他の人のゴミを見られる。
72時間で工場に運ばれ、二度と見られない。

いいね・コメント・フォロー・ユーザー名・プロフィール・ランキング・共有は実装しない。
評価手段を置いた瞬間に、発信側が最適化を始める。

## ファイル

- `index.html` — 画面の器
- `style.css`  — 色、影、跳ね方、呼吸
- `app.js`     — 島の生成、放飼場、個体、入場券、投稿フロー
- `data.js`    — 地域定義と初期個体（島が無人に見えないための最小限）
- `judge-prompt.md` — Claude API に渡す飼育員のプロンプト

## いま動くもの

1. 島のマップ（影・左上光源・砂浜のフチ・1本の園路・川・不規則な放飼場・わずかなパース・手描きのゆらぎ）
2. 背景の動き（木の揺れ、波、雲の影が横切る、来園者の白丸）
3. 放飼場の中と weight_class 別の跳ね（light はふわりと高く流される / medium は素直に / heavy は震える）
4. 個体の詳細（名前・国旗・現地時刻・飼育員の記録・工場まであと N 時間）
5. 投稿フロー（撮影 → 自動切り抜き → 判定）
6. 入場券（24時間。初回のみ、支払う前に5匹だけ見られる）
7. 72時間で工場行き

## まだ繋がっていないもの

- **判定** — `app.js` の `CONFIG.judgeEndpoint` が null のあいだは仮の飼育員が答える。
  サーバー側を立て、`judge-prompt.md` の内容で Claude に渡す。API キーはクライアントに置かない。
- **切り抜き** — いまは縁からの領域拡張によるブラウザ内処理。
  背景と対象の色が近いと残る。`@imgly/background-removal` などに差し替える前提。
  ここが甘いと部屋が写り、盛る余地が生まれる。このプロダクトの生命線。
- **保存** — いまは端末の localStorage。他人のゴミは初期個体で代用している。
  サーバーに移す際も、保存するのは切り抜き後の画像のみ。元画像は持たない。
