# Trash zoo — 実装ブリーフ（原典）

これはこのプロダクトの発案者が最初に書いた仕様である。
`AGENTS.md` はここから運用上の要点だけを抜き出したもので、判断に迷ったときの最終的な根拠はこちらにある。

## 0. このプロジェクトが何であるか

世界中の人が、その日出した「食べ物のゴミ」を1つ投稿する。投稿するとゴミは自動で切り抜かれ、動物園のような島に「放される」。他の人が出したゴミを見るには、自分もゴミを出さなければならない。ゴミは一定期間で「工場」に運ばれ、二度と見られなくなる。

これはSNSではない。いいね、コメント、フォロー、共有、ランキング、通知バッジは一つも実装しない。

### 解こうとしている課題

SNSでは全員が良い部分だけを見せるため、誰もが「自分以外は上手くやっている」と誤解している。そして劣等感を打ち消すためにさらに盛るので、ループが加速して誰も降りられない。研究では、社会的比較が完璧主義的自己呈示（Perfectionistic Self-Presentation）を誘発すること、逆に「本物だと感じられる呈示」に触れると心理的ダメージが緩和されることが示されている。

このプロダクトが提供するのは、編集されていない他人の生活の証拠である。加工できないものだけを流通させることで、歪んだ比較の分母を静かに補正する。

説教はしない。環境問題も語らない。ユーザーには「他の国の人がどんなものを食べているか見られる場所」としてだけ体験される。効果は構造が担い、メッセージは一切表に出さない。

### なぜゴミなのか（実装判断に迷ったら必ずここに戻る）

- ゴミは撮影された時点で「見せる意図」がない。この世で唯一、盛れないコンテンツ。
- 食べ物のゴミに限定するのは、生活が最も色濃く出るから。かつ「味」という語れる内容があるから。
- 切り抜きによって、部屋・服・ネイル・照明といった演出の余地が物理的に消える。ルールで禁止するのではなく、盛れる場所そのものを消す。

## 1. 絶対に守る設計原則

実装中に迷ったら、この5つで判断する。機能追加の提案がこれに反する場合は却下する。

1. **発信者が編集できない** — 撮影対象・見せ方の裁量をユーザーから外す。切り抜きは自動、説明文の生成も自動。ユーザーが書ける自由記述欄は一切設けない。
2. **誰が見るかわからない** — 見られる相手が想像できた瞬間に人は加工する。投稿先の地域は選べない。
3. **投稿の動機が「見せたい」ではない** — 投稿は入場券であり、対価である。承認を求める行為にしない。
4. **見る側に評価手段がない** — 評価があると発信側が最適化を始める。
5. **平凡なものほど価値がある** — 特別な日を投稿したくなる構造を作らない。

### 実装してはいけないもの

いいね / コメント / 返信 / フォロー / DM / ユーザー名 / プロフィール / アイコン / ランキング / 「人気の放飼場」/ 投稿数の個人表示 / SNS共有ボタン / 連続ログインボーナス / デイリーミッション / 通知の乱発。

これらは全て、原則3〜5を破壊する。

## 2. 中核となる体験ループ

```
入園しようとする
  → 今日まだゴミを出していない場合、投稿を求められる（入場券）
  → 撮影 or 選択 → 自動で切り抜き → AIが判定・分類・説明文生成
  → 「あなたの子は東アジアに送られました」
  → 島のマップへ。自分の子がいる放飼場が一度だけ光る
  → その放飼場へ向かう（途中で他の放飼場が目に入る）
  → 放飼場を開く → ゴミたちが跳ねている → タップで詳細
  → 数日後、自分の子は「工場に運ばれました」と表示され、消える
```

### 入場券の運用

- 1回投稿すると24時間閲覧可能。毎回払わせない。
- 初回のみ、投稿前に3〜5匹だけ見られる。何が起きている場所か分からないまま支払いを求めるのは離脱要因になる。等価交換の思想は保ちつつ、体験は途切れさせない。
- 期限が切れたら、マップは見えるが放飼場の中は霞んで見えない。締め出すのではなく「また明日」と伝える。

## 3. 投稿フロー

### 撮影と切り抜き

- カメラ or カメラロールから1枚。
- **背景を自動除去し、ゴミだけを切り抜く。** ここがこのプロダクトの心臓部。切り抜きが甘いと部屋が写り、盛りの余地が生まれる。
- 切り抜き結果はユーザーに確認させるが、加工手段は与えない。「これでいい / 撮り直す」の二択のみ。フィルタ、トリミング、明るさ調整は一切実装しない。

### AI判定（Claude API / vision）

投稿された画像に対し、以下をJSONで返させる。

```json
{
  "is_food_waste": true,
  "name": "ココナッツ味のビスケットの袋",
  "category": "袋 | 容器 | 缶 | 箱 | 瓶 | その他",
  "weight_class": "light | medium | heavy",
  "keeper_note": "ココナッツの甘い香りが強く、噛むほどに癖になる味です。現地では朝の紅茶と一緒に食べられます。",
  "confidence": 0.0
}
```

- `is_food_waste` が false の場合は投稿を弾く。食べ物のゴミ以外は受け付けない。
- 人物、文字だらけの書類、明らかに食品と無関係なものも弾く。
- `weight_class` は後述のアニメーションに使う。
- **プロンプトには「飼育員として書け」と明示する。** これがこの世界の声を決める。

### 飼育員の声（keeper_note のトーン指定）

- 一人称は使わない。淡々と、しかし対象への敬意がある。
- 味・香り・食感・その国での食べられ方に触れる。読んだ人がその食べ物の解像度を得られることが目的。
- 「おいしそう」「人気です」など評価語は使わない。観察のみ。
- 60〜90字程度。長いと読まれない。
- 例：「ココナッツの甘い香りが強く、噛むほどに癖になる味です。現地では朝の紅茶と一緒に食べられます。」

### 地域の振り分け

- 端末のタイムゾーン or 位置情報から地域を判定。ユーザーには選ばせない（原則2）。
- 地域区分：東アジア / 東南アジア / 南アジア / 中東 / アフリカ / 西欧 / 北欧 / 東欧 / 北米 / 中南米 / オセアニア。
- **現地時刻を必ず記録する。これが最も生活を漏らす情報になる。** 深夜2時に菓子を食べた誰かがいる、という事実は国名より雄弁。

## 4. 工場（ゴミの一生）

- 各ゴミは投稿から **72時間** で「工場に運ばれました」と表示され、島から消える。
- 二度と見られない。復活も、アーカイブも、自分の過去投稿一覧も作らない。消えることが体験の一部。
- 自分の子が工場に行く時は、静かな一度きりの通知のみ。「あなたの子は工場に運ばれました。ありがとうございました。」煽らない。
- 放飼場のプレートに「本日 3匹 出荷」とだけ淡白に表示。急かす文言は使わない。事実だけ置くと、勝手に見に行く。

工場行きは表向き「密度の管理」だが、実質的には今すぐ見に行く理由を作る装置である。永久保存にすると、この体験は死ぬ。

## 5. ビジュアル方針

参照するのは『あつまれ どうぶつの森』のマップUI。ただし模倣ではなく、その質の高さの理由を分解して適用する。

### 全体の質を決めている要素（必ず全て実装する）

1. **すべてのオブジェクトに影がある。** 放飼場、木、看板、プレート、来園者、跳ねているゴミ。影があるだけで平面のシルエットが「置いてあるもの」になる。UIパーツも例外にせず、下に1枚影版を敷く。
2. **光源は左上に統一。** すべてのオブジェクトの左上側にハイライト、右下側に陰。統一されていないと安っぽくなる。
3. **島を海で囲む。** 境界が生まれ、「この中が全部」が一目で伝わる。緑が画面いっぱいだと園の範囲が分からない。
4. **緑と海の間に砂浜のフチを挟む。** 輪郭が硬くならない。可愛らしさの半分はここから来る。
5. **園路は1本の曲線。** グリッド配置は「一覧」に見えるが、曲がった道は「歩く場所」になる。先が見えないことで次が気になる。
6. **川を通す。** 機能はないが画面を分割し、放飼場が散らばっていても迷子にならない。川岸に濃い線を入れて地形として成立させる。
7. **放飼場は円形、大きさも位置もばらばら。** 揃っていると管理施設に見える。散らすと地形に合わせて作られた園に見える。
8. **放飼場の地面の色を地域ごとに変える。** 東アジアは草地、北欧は寒々しい枯草、南米は乾いた土。生息環境の再現という動物園の作法をなぞりつつ、国の空気を色だけで伝える。

### 静止画では出せなかった、実装で必ず埋めるべき3点

これらが未実装だと「AIが作った図」に見える。優先度は高い。

1. **わずかなパース。** 完全な真上視点は図面に見える。マップ全体を数度傾けるか、オブジェクトに軽い高さを持たせる。
2. **手描きのゆらぎ。** 数式で描いた曲線は正確すぎて機械的になる。島の輪郭、園路、放飼場の縁に微細な不規則性を持たせる。線幅も一定にしない。
3. **背景が呼吸していること。** 跳ねるゴミ以外にも動きを入れる。木がゆっくり揺れる、波が寄せる、看板が微かに揺れる、雲の影が島を横切る。背景が静止していると全体が死ぬ。**これが最も効く。**

砂浜      #F5E6BC   砂の縁 #E4D2A2

### タイポグラフィ

- 日本語は Noto Sans JP。ウェイトは400と500のみ。太すぎると子供っぽくなりすぎる。
- 数値・時刻は等幅（JetBrains Mono など）。現地時刻は情報の主役なので、等幅で読みやすく置く。
- すべて文中表記。全角の多用は避ける。

## 6. 画面構成

### 6-1. 島のマップ（メイン画面）

- 海に浮かぶ島。中央に管理棟。周囲に放飼場が5〜7個、不規則に配置。
- 各放飼場のプレートに「地域名 + 現在の匹数」。
- **空の放飼場を必ず1つ用意し、管理棟の近くに置く。**「まだ誰もいません」。一番目に入る位置に空きがあると、入園者が最初に気になる。自分が最初の1人になれる入口。
- 他の来園者を小さな白丸で表示。名前も姿もなし。cursor camp と同じ低情報性が安全性と想像力の源。
- 上部に「来園 N人」「本日 N匹」。それだけ。

### 6-2. 放飼場の中

- タップで開く。ゴミが7〜9匹、跳ねている。
- **タップ判定に十分な間隔が必要なので、匹数の上限はタップしやすさから決める。** 9匹を超える場合は同地域に第二放飼場を新設する形にし、1つの放飼場に詰め込まない。詰め込むとゴミ捨て場に見える。
- 跳ね方を `weight_class` で描き分ける：
  - light（袋、包み紙）— ふわりと高く浮き、着地が遅い。風に流される
  - medium（箱、カップ）— 素直に跳ねる
  - heavy（缶、瓶）— ほとんど跳ねず、小刻みに震える。たまに倒れる
  - **この描き分けが「生き物らしさ」の正体。** 全部同じ跳ね方だと静止画を動かしただけに見える。
- 個体ごとに跳躍周期をずらす。同期すると機械的になる。

### 6-3. 個体の詳細

- タップすると個体が手前に来て、飼育員のプレートが表示される。
- 表示内容：名前 / 国旗 / 現地時刻 / keeper_note。それだけ。
- 「工場まであと N時間」を淡白に添える。カウントダウンは煽らない。静かに置く。

### 6-4. 入園時の案内

- 「あなたの子は東アジアに送られました」
- その放飼場だけが一度だけ光る。到着したら消える。案内は一回きり。
- これにより、自分の子会いたさに入り、道中で他の放飼場が目に入り、結果として他国のゴミも見る、という動線が生まれる。

## 7. 技術構成

- フロントエンド：React + TypeScript。マップとアニメーションは SVG で構築（拡大縮小に強く、個体ごとの操作がしやすい）。動きが重くなる場合は Canvas への切り替えを検討。
- バックエンド：投稿保存、地域振り分け、72時間での自動削除ジョブ。
- 画像処理：背景除去（`@imgly/background-removal` などのブラウザ内処理、または専用API）。切り抜き品質はこのプロダクトの生命線なので、複数手法を比較して最良を選ぶこと。
- AI：Claude API（vision）で判定・分類・keeper_note 生成。
- ストレージ：**切り抜き後の画像のみ保存。元画像は保存しない。** 背景に写った生活情報を持たない設計にする。
- 匿名性：アカウントは端末単位の匿名ID。メールもパスワードも不要。個人を特定する情報を一切持たない。

## 8. 文言のトーン

- 施設として話す。「私が」とは言わない。
- 淡々と、しかし冷たくない。事実だけを置く。
- 感嘆符を使わない。煽らない。急かさない。
- 例：
  - 「あなたの子は東アジアに送られました」
  - 「本日 3匹 出荷」
  - 「まだ誰もいません」
  - 「あなたの子は工場に運ばれました。ありがとうございました。」
  - 「今日はまだ入場券がありません」

## 9. 実装順序

1. マップ画面の静的ビジュアル（影・光源・ゆらぎ・パースを最初から作り込む。後付けは効かない）
2. 背景の動き（木の揺れ、波、雲の影）— ここまでで世界が生きているか確認する
3. 放飼場の中と、weight_class 別の跳ねアニメーション
4. 個体詳細
5. 投稿フロー（撮影 → 切り抜き → AI判定）
6. 入場券のゲートと24時間の管理
7. 72時間での工場行き
8. 入園時の案内演出

**1と2が終わった時点で一度立ち止まり、「これは触りたくなるか」を確認する。** ここが弱いまま先に進むと、機能を足しても取り返せない。

## 10. 品質の判断基準

実装中、以下を自問すること。

- 背景が静止していないか。動いていなければ死んでいる。
- 影のないオブジェクトはないか。
- ゴミの跳ね方は全部同じになっていないか。
- どこかに「盛れる余地」を作っていないか。加工、自由記述、選択の自由はすべて疑う。
- 評価に繋がるものを追加していないか。数字を出すなら、それは増やす努力ができない数字か。
- 文言が煽っていないか。

## 実装が原典から意図的に外れている点

- **React + TypeScript ではなく、素の HTML/CSS/JS で作られている。** ビルド無しで即座に配信でき、SVG も同じように扱えるため。React に載せ替える理由が生まれたら移せばよい。
- **放飼場の中は「跳ねているゴミだけ」ではなく、動物園の展示場として作られている。** 空、地域ごとの遠景、岩の擁壁、掘られた地面、手前のガラス柵、そしてそれを覗き込んでいる来園者。原典 6-2 の要件（跳ね分け、周期のずらし、タップ間隔）はその中で満たしている。
